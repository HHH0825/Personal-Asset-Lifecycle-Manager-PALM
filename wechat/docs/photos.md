# 物物记：物品照片选择与编辑

## 使用流程

1. 在新增或编辑物品的“照片与备注”区域点击“选择照片”或“重新选择”。
2. 选择“从相册选择”或“拍一张照片”，每次一张，拍照默认后置摄像头。取消不修改当前照片。
3. 可直接保存，也可点击“裁剪”打开微信原生正方形取景界面，或点击“旋转”顺时针转 90°。预览使用完整图片展示，避免误把缩略显示当成裁剪结果。
4. 点击“保存物品”才会上传最终图片；不修改手机相册原图。新增物品会将最终编辑图片另存为本机草稿文件，以便重启后继续；编辑已有物品仍只生成临时图片。上传失败仍保留已保存的物品，可进入详情重新编辑上传。

已有物品进入编辑后会下载照片作为预览。没有编辑或重新选择时，只保存物品字段，不重新上传原照片；下载失败也不会删除原照片。可点击“重试读取”或重新选择。

新增草稿的照片替换先保存新副本，再清理旧副本；创建成功后，待上传流程结束再清理草稿文件。草稿缺失或保存失败不删除相册原图，详见 [录入草稿](drafts.md)。

## 兼容与权限

- 微信基础库 2.26.0 起支持 `wx.cropImage`；调用前检查能力，缺少时提示更新微信。仍可选图、拍照、旋转或保存。
- 相册和相机由 `wx.chooseMedia` 调用，使用明确的 `sourceType`。拒绝权限、相机不可用或文件处理失败会显示提示；用户自行处理微信隐私授权和手机权限，不自动打开设置或重复请求。
- 旋转使用原生 Canvas 2D，先处理相机 EXIF 朝向，再顺时针转 90°；最长边不超过 1600px、不放大小图，以质量 0.85 输出 JPEG。
- 上传仍使用原有认证照片接口；服务端检查最多 5 MB，支持 JPEG、PNG、WebP。相册选择请求压缩，但不承诺所有图片一定符合上限；服务端拒绝时展示原有上传失败说明。
- 照片处理期间禁止重复操作及保存。离开页面、销毁页面或切换账号后，旧回调不能替换当前图片或新账号内容；原生相机界面暂时覆盖当前页面时仍可正常返回照片。

## 验证方式

前端测试使用真实页面和照片工具函数，模拟微信回调，覆盖来源、取消、权限失败、裁剪结果、旋转尺寸、EXIF 朝向、编辑失败、上传最终路径、旧照片预览与旧响应保护。Canvas 导出参数及像素坐标变换有独立检查。

实际拍照、原生裁剪和 Canvas 输出必须另在 Android、iPhone 验证：拍摄横图和竖图，连续转四次核对朝向，裁剪后取消与确认各一次，保存并重进详情核对照片，拒绝权限后从相册重试。开发者工具可能不支持真实相机或原生裁剪，不能据模拟器判断真机已通过。

## 加载与重试

清单和照片墙读取最长边 480px 的 JPEG 缩略图；详情、原照片编辑继续读取最长边 1600px 的清晰版本。均保留照片比例，小图不会放大。详情已有缓存缩略图时先展示，再替换为清晰版本；裁剪与旋转只使用清晰版本。

照片区域大小固定。读取中显示纸色提示；失败显示类型插画及“重试照片”，不会自动反复下载。点击清单的重试不会进入详情。网络失败时，当前已显示的清单和照片会保留；退出或切换账号时清空。清单数据本身未加载成功时不会伪装成空收藏。

`utils/photo-cache.js` 在当前会话内共用下载：按服务地址、会话、物品、照片版本和尺寸区分，最多 3 个并发，屏幕内照片优先，下方约一屏预加载。返回清单复用文件；缓存最多 60 张或 20 MB，超限淘汰最近最少使用的照片。系统清理临时文件后重新下载。缓存没有写入持久存储，重启小程序后可重新下载。

页面离开后撤销该页面等待的下载；其他页面仍需要的同一请求可继续。账号切换、会话失效、照片更新和物品删除会取消或使对应缓存失效，旧结果不能重新写入页面。只清理本模块取得的下载文件，草稿和相机文件独立管理。

新上传同时生成缩略图；旧照片首次请求时补生成，原有照片文件不被改写。照片替换、移除、到期清理和永久删除同时清理缩略图，无须数据库迁移。更新源码后重启后端并完整编译小程序。

可运行 `node --test tests/photo-cache.test.cjs` 和 Python 测试中的 `test_photos.py`。请求与字节数对照可运行 `node tools/photo-benchmark.cjs .venv/Scripts/python.exe`；该工具使用临时数据库、生成图片和缓存回放，不读取用户照片，不测量真实手机显示时间。真机步骤见 [手机验收清单](device-check.md)。
