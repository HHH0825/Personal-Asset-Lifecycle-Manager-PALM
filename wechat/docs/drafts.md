# 物物记：新增物品草稿

## 怎么使用

1. 登录后点击“新增”，填写名称、分类、类型、状态、购买日期、价格、保修日期或备注。
2. 停止输入约 500 毫秒后，表单下方显示“草稿已保存到本机”。离开页面或切到后台时也会补存。
3. 选择、裁剪或旋转照片后，最终结果另存为本机草稿照片；原相册文件不会被修改。
4. 再次打开“新增”，提示会显示草稿名称和最后保存时间。点击“继续填写”恢复；“暂不填写，返回清单”保留草稿。
5. “重新填写”及表单底部的“丢弃草稿”需要确认，清除这份填写内容和草稿照片。

未修改的空表单不会产生草稿。每个账号在当前设备只保留一份新增草稿，编辑已有物品不保存草稿。

## 保存成功与异常

- 创建物品成功即标记草稿已完成，不再作为新增草稿恢复；照片上传结束后才清理本机文件。
- 照片上传失败会提示“物品已保存”，应进入详情重新编辑上传。当前表单再次提交会编辑已创建的物品，不再创建第二件。
- 本机空间不足或存储写入失败时显示“草稿未保存”，当前填写内容仍在，允许正式提交。不要将这个提示当作已经保存。
- 恢复时照片丢失，其他字段先恢复，提示重新选图。
- 旧上传的清理只针对原草稿，不清除随后新建的草稿；账号切换后的旧照片回调不能写入新账号草稿。

## 数据存在哪里

草稿按“后端地址＋稳定用户编号”区分，不保存登录令牌。修改昵称不会改变草稿归属。同一账号退出后再登录仍可恢复；其他账号不可读取。

元数据使用小程序本地存储，照片副本放在 `wx.env.USER_DATA_PATH`。不上传云端，不跨设备同步，不与单机网页版共享。卸载小程序、清除微信本地数据或系统回收本地数据可能使草稿丢失。

## 开发入口

| 文件 | 职责 |
| --- | --- |
| `miniprogram/utils/drafts.js` | 账号作用域、存储、照片复制、完成标记与清理 |
| `miniprogram/pages/editor/index.js` | 500ms 保存、页面离开补存、恢复提示及提交流程 |
| `miniprogram/pages/item/index.js` | 详情折叠、更多操作、返回位置及迟到响应保护 |
| `tests/draft-detail.test.cjs` | 本轮草稿及详情行为测试 |

照片替换先复制新文件，成功写入元数据后再清理旧文件；复制或存储失败保留原草稿。每份草稿有独立标识，旧上传结束时不会误清理新的填写内容。页面输入和照片回调通过修订序号、登录会话校验丢弃过期结果。

## 定向检查步骤

使用独立测试账号和数据：

- 填写名称和备注，退出录入，再打开新增；完整重启后再次恢复。
- 选择照片、裁剪和旋转后返回，重新进入确认最终照片；原相册图片不应改变。
- 取消丢弃确认应保留；确认丢弃后再次新增应是空表单。
- 切换账号不出现其他人的草稿，换回原账号应可恢复。
- 模拟本机写入失败和草稿照片丢失，检查提示与正式提交。
- 保存物品但模拟照片上传失败，不应出现第二件物品或完成草稿恢复提示。
- 展开详情资料、纪念和全部记录，进入编辑再返回；关闭后重新打开应恢复默认折叠。
- 已处置物品、购买当天“暂无”、零价格、负净成本和长名称继续正确显示。

在 `wechat/` 下运行 `node --test tests/draft-detail.test.cjs`。测试使用微信 API 的测试桩，不等同于真机文件系统、权限或后台生命周期验收。实际完成的模拟器与真机项目分别记录在 [界面验收记录](visual-check.md)。
